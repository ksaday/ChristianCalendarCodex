# Calendar conversion design

All adapters take the same integer D. A displayed label identifies a calendar and convention. Inverse search requires those fields and validates the date before moving the cursor. A release manifest declares the provider, revision, inclusive coverage and evidence actually checked. **Verified V2 range today is empty for every adapter** because this phase specifies future software. The following are proposed release targets. [data models and interfaces](10-DATA-MODELS-AND-INTERFACES.md) · [verification and test plan](12-VERIFICATION-AND-TEST-PLAN.md)

## Gregorian and Julian

Both proleptic rules use astronomical y internally. CE k maps to k, BCE k to 1−k for k≥1. Display y≤0 as (1−y) BCE. Reject 0 BCE and 0 CE. Gregorian leap years are divisible by 4 except century years indivisible by 400. Julian leap years are divisible by 4. These tests also apply at year zero. Reject an impossible day using the chosen rule.

**Forward conversion for either calendar.** With floor division throughout, set a=floor((14−month)/12), Y=y+4800−a, M=month+12a−3. Set B=day+floor((153M+2)/5)+365Y+floor(Y/4). Return B−floor(Y/100)+floor(Y/400)−32045 for Gregorian or B−32083 for Julian. Both label civil noon with an integer. Gregorian behavior derives from the baseline [calendar script](../../js/calendar.js).

**Inverse conversion without epoch limits.** Use March 1 of astronomical year 0 as the origin for each adapter, computed by its forward rule. Euclidean-divide D minus that origin by P, where (P,L)=(146097,400) Gregorian or (1461,4) Julian. Beginning at year L·quotient, binary-search the L March starts for the last one ≤ D. Search the twelve month starts in that March–February year for the last ≤ D, treating January and February as months of the next astronomical year. Day = 1+D−monthStart. The repetition of leap patterns proves translation by P preserves month/day and adds L years, including for negative eras. Each search has a bounded number of comparisons.

**Range and provenance.** Both mathematical definitions cover every integer JDN subject to resources. Release proof covers complete cycles by translation, supplemented by exhaustive cycle tests and checks in distant eras. Proleptic output before local adoption is a calculated label. Default conversion never skips October dates. A future historical-reform profile must name a jurisdiction and cutover; the 1582 example joins Julian October 4 to Gregorian October 15 on consecutive JDNs. The USNO converter uses a cutover, so select the matching calendar when comparing historical fixtures. Any unsupported historical profile returns an explicit status. [USNO conventions](https://aa.usno.navy.mil/data/JulianDate)

## Calculated Hebrew

Use the fixed Hebrew calendar with Tishrei as the year boundary. Leap years in the 19-year cycle are 3, 6, 8, 11, 14, 17 and 19. Calculate successive Rosh Hashanah fixed days using mean lunar conjunction and the four postponement rules via a pinned, audited fixed-calendar provider. Year length determines variable Cheshvan and Kislev, and leap status distinguishes Adar I and II. Starting at Tishrei 1, accumulate validated month lengths to compute a fixed day. For inverse search find the bracketing year starts and month start. Provider contract uses Rata Die, with RD 1 = Gregorian 0001-01-01, D=RD+1721425. Pin the upstream revision, review licensing and validate the provider’s argument ranges before integrating. [Hebcal implementation](https://github.com/hebcal/hdate-js)

Proposed supported interval is Gregorian 1901-01-01 through 2100-12-31 inclusive for MVP. Guard D before narrowing to provider numbers. For reverse requests bound candidate years by the converted coverage endpoints, validate month identity and check final D. Partial years at either end are valid only for days inside coverage. Display the Hebrew date of the daytime portion of the civil day. Sunset rules apply only to a separately entered instant and location. A fixed-calendar projection into an ancient observational community cannot establish its actual observed month. Outside coverage return unsupported. Release requires daily round trips across the interval and independent year-type/leap witnesses. [Published April 2026 fixture](https://www.hebcal.com/converter?g2h=1&gd=4&gm=4&gy=2026)

## Chinese lunisolar

Use a versioned Hong Kong civil-day profile. Modern month beginnings follow the local day of astronomical new moon. Month eleven contains the winter solstice. In a 13-month interval between consecutive month elevens the first eligible month without a principal solar term repeats the preceding month number. Distinguish all 24 terms from the 12 principal terms used for intercalation. Geographic day assignment matters for events near midnight. Earlier dynasties used different rules and meridians. An arbitrary browser locale cannot select this convention. [HKO solar terms](https://www.hko.gov.hk/en/gts/time/24solarterms.htm)

Propose a licensed, offline month-start index for the HKO published Gregorian 1901–2100 window. Store exact start D, lunar year identified by Gregorian year of its new year, month, leap flag and length. Preserve partial first/last months, including previous lunar-year identity in January. Require endpoint evidence or store verified partial-day records. Binary-search month starts for display, use a keyed reverse index for input, recheck inclusive coverage. Derive no astronomical predictions outside the published interval. A table lookup can reproduce a published label even when that source cautions that a predicted event near midnight could shift by a day. Attach that warning to affected entries and dependent month labels. [HKO tables and exceptions](https://www.hko.gov.hk/en/gts/time/conversion.htm)

Future acceptance requires daily comparison to the pinned publication, independent new moon and solar-term checks on selected leap boundaries, and exact inverse results including partial months. A table and its own transcription share a source. No inference of independent historical confirmation follows from agreement. Unresolved redistribution rights block packaging that dataset; evaluate a permissively licensed calculation provider against the same profile or defer public release of the affected coverage. [2026 HKO almanac](https://www.hko.gov.hk/en/gts/astron2026/files/HKO_almanac_2026.pdf)

## Additional adapters

Register a unique convention ID, version, coverage predicate, two conversion directions, field schema and verification evidence. An uncertain result includes the candidate label and reason when supported by evidence. Unsupported results carry reason and range only. A failed adapter affects one row. Historical events, eclipse predictions and recorded observations would be separate provenance-bearing annotations. [system architecture](09-SYSTEM-ARCHITECTURE.md)
