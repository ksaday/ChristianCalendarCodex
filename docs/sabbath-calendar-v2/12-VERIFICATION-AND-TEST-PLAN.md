# Verification and release gates

**Status.** These are executable acceptance specifications for a future implementation. This design audit checked the baseline fixtures arithmetically. An adapter earns a verified interval only after its release suite passes with archived evidence.

| Case | Procedure and required result |
|---|---|
| T01 · anchor and spacing | Check every index in the table in [negative sabbath numbering](05-NEGATIVE-SABBATH-NUMBERING.md) plus #3. Generate seeded signed integers from 1 to 4096 digits, record seeds and minimized failures. For each n,k verify S(n+k)−S(n)=7k, inverse(S(n))=n and weekday Saturday. |
| T02 · day partition | For each generated index and all offsets 0…6, check cycle, inclusive and strict neighbors against [mathematical foundation](04-MATHEMATICAL-FOUNDATION.md). Include D=−1,0,1 and A±1, A±7. Only offset zero returns an exact index. |
| T03 · magnitude | Compare serialized results in two JS engines with a separate arbitrary-integer oracle. Cluster around ±2^53 and powers of ten. Count core arithmetic operations on #1 and a 4096-digit index; week jump count is constant. Oracle agreement supplements the algebraic proof. |
| T04 · civil calendars | Enumerate all 146097 Gregorian and 1461 Julian days in March-based periods and translate periods to negative and very large years. Compare adjacent labels against a separately written month-length enumerator. Gregorian 1900/2100 common, 2000 leap, Julian 1900 leap. Astronomical 0 Dec 31 precedes 1 Jan 1 and displays 1 BCE. JDN 0 is Julian 1 Jan 4713 BCE. Julian 1582-10-04 = 2299160; Gregorian 1582-10-15 = 2299161. In proleptic Gregorian input October 5–14 also exist. Compare modern days to independent ordinal implementation and historical cutover to USNO. |
| T05 · fixed Hebrew | Daily reverse/forward round trips over claimed coverage. Check common, deficient and complete year lengths, Adar I→II, leap→common year transition and Tishrei boundary. Reject Adar II in a common year and day 30 in a 29-day month. Gregorian April 4 2026 ↔ 17 Nisan 5786. If using Hebcal, its web converter is a regression witness only. Obtain an independently published Jewish communal almanac with documented lineage for leap/year-start samples before release. |
| T06 · Chinese | Compare every supported civil day to pinned publication; compare lunar year/month/day/leap flag both directions. Test 2026-02-17 = lunar 2026 month 1 day 1, leap-month first and last days, regular and leap namesake and next month. Include HKO's near-midnight warning dates. Use independent astronomical event times with the correct local-day convention for selected transitions; investigate disagreements instead of voting across libraries. |
| T07 · coverage | For each bounded adapter exercise first−1, first, last, last+1 in both directions using endpoint labels and their valid adjacent dates. Inject missing table, uncertain entry and delayed stale response. No invented label or mixed-revision rows. Reject invalid fields separately. |
| T08 · selection | Execute all five [ui ux design](11-UI-UX-DESIGN.md) flows, including manual plus/minus and #0. Assert raw D and row-specific results, then submit invalid input and verify D unchanged. |
| T09 · accessible UI | At 320px and desktop widths, 200% zoom and keyboard only, search, zoom all five scales and open/close details. Screen reader announces selected day once; focus returns. Step January 31→February and across 1 BCE/1 CE. Verify same-day alignment and preserved D on zoom. |
| T10 · rendering | Alternate 1000 jumps near zero and ±10^100 at every zoom. Count ≤510 tick elements and ≤1024 cached conversions. Compare pointer, cursor and keyboard deltas to BigInt reference at viewport edges and one-pixel collisions. Record timings and hardware; any jump that walks intervening weeks fails. |
| T11 · boundaries | Round-trip canonical JSON strings including a computed 4097-digit JDN, reject JSON numbers, unknown versions, partial parses, malformed signs and excessive bytes. Include markup and exponent forms. No DOM interpretation, selection mutation or precision loss on errors. |
| T12 · compatibility | Check all four fixtures in [existing project analysis](02-EXISTING-PROJECT-ANALYSIS.md), anniversary tag only on April 4 in 2026, year-33 exception, inclusive countdown on Saturday, Friday countdown one day, pre-anchor seal and positive 1000 milestone. Smoke-test legacy month navigation, Today and keyboard popover. Freeze local civil date for reproducibility. |
| T13 · interpretation | In Mode A search a distant negative index. Later toggle an approved aligned synthetic boundary and compare D and n before/after; misaligned boundary is rejected. Uncertain ranges never become a computed first Sabbath. |
| T14 · observance | Later supply DST transition, ordinary sunset, differing zones, unknown historical offset and polar no-event cases. Validate both instants independently, or show qualified/unavailable result. Mathematical D and n remain identical. |
| T15 · delivery | Open original page and static V2 entry with only packaged assets, then block external requests. Run all searches inside coverage and a distant jump. No required external request or secret. |

**Promotion order.** Gate G1 requires T01–T03 and core transport precision checks before integrating any calendar. Gate G2 requires T04–T07 with versioned sources, licensing and an explicit coverage manifest per adapter. Gate G3 requires T08–T12 and T15 plus Mode A portion of T13. Future gate G4 requires complete T13 or T14 before enabling its respective feature. Any unexplained mismatch, missing independent evidence for declared coverage, failing legacy fixture or silently rounded UI coordinate blocks the corresponding gate.

Record baseline hash, provider revisions, evidence lineage, tested interval, seed, runtime and platform with each result. Translational proofs support distant civil years beyond enumerated examples. Two ports of the same published algorithm can detect transcription differences but cannot independently establish its epoch. Use dated observations or almanacs alongside differential tests. Source endpoints and limitations are in [calendar conversion design](07-CALENDAR-CONVERSION-DESIGN.md).
